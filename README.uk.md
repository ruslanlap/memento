# memento

> Прокинься. Перевірь нотатку. Продовж роботу.

Продовж уччорашню роботу в іншому агенті — із доказами того, що досі правдиве.

[English](./README.md) | Українська

## Швидкий старт

Встановіть через [Skills CLI](https://github.com/vercel-labs/skills) (Node.js ≥22.20 для протестованої версії CLI; нижче — суто Git-альтернативи):

```sh
npx skills add ruslanlap/memento --skill memento
```

Перед переключенням сесій попросіть: **«Використай memento, щоб зберегти checkpoint для цього завдання.»**
У новій сесії: **«Використай memento, щоб відновитись із MEMENTO.md; перевірь наступний крок проти поточних файлів.»**

Потрібен агент із доступом до файлів і робочим простором, що зберігається між сесіями. Сам скіл не має рантайм-залежностей.

`memento` — портативний скіл, який дає кодинг-агентам надійну пам'ять завдань на доказах: між втратами контексту, перерваними сесіями, передаваннями роботи та переключеннями моделей.

Кожен критичний claim несе своє джерело і стан, у якому його перевірено. Наступний агент перевіряє те, що має значення, перш ніж продовжити.

## Ідея

Натхнено фільмом Крістофера Нолана «Пригадати все» (*Memento*, 2000): скіл перетворює систему пам'яті фільму на безпечніший агентний протокол:

| Прийом фільму | Значення для агента |
| --- | --- |
| Татуювання | Стійкі обмеження й рішення з доказами |
| Полароїди | Поточний спостережуваний стан |
| Клаптєві нотатки | Гіпотези, які не можуть авторизувати дію |
| Закреслені нотатки | Хибні твердження, які майбутній агент міг би повторити |
| Наступна сцена | Одна конкретна, перевірювана наступна дія |

Перед ризикованою дією агент відновлює причинність у зворотному напрямку:

```text
пропонована дія -> твердження, що її підтримує -> поточний доказ
```

Якщо ланки немає або вона застаріла — спершу перевірка. Це запобіжник, якого не вистачало системі Леонарда.

## Чим відрізняється

- **Вибіркова верифікація:** перевіряються завдання, робочий простір і докази, потрібні для наступної дії.
- **Відстеження джерела:** різні категорії — спостереження, гіпотези, рішення та спростовані твердження.
- **Межа повноважень:** збережена заява про одобрення не може надати дозвіл на виконання команди.
- **Мінімальна поверхня:** один `SKILL.md`, один проєктний `MEMENTO.md`, без баз даних, ембедингів, хуків, рантайму чи залежностей.
- **Повага до дозволів:** автоматична активація ніколи не надає дозволу змінювати робочий простір.

Повний виготовлений checkpoint див. у [`examples/MEMENTO.md`](./examples/MEMENTO.md).

## Реконструйований кейс: запуск цього репозиторію

20.09.2026 перша перевірка `gh auth status` повідомила про недійсний збережений токен, заблокувавши публікацію. Далі device-логін у GitHub вдався, `main` запушено, CI пройшов. Наївний append-only журнал залишив би **«Автентифікація GitHub зламана»** як актуальне твердження й після того, як воно стало хибним.

Події вище відбулися під час розробки. Знімок нижче реконструйовано постфактум; жоден незалежний агент з нього не відновлювався, тож це не бенчмарк ефективності:

```markdown
## Polaroids
- `ruslanlap/memento` публічний, відслідковує `main`. — Evidence: `gh repo view ruslanlap/memento`
- Валідація пройдена для коміту `7f7ae5c`. — Evidence: GitHub Actions run `35511302389`

## Crossed-out Notes
- «Автентифікація GitHub зламана.» — Invalidated by: успішний device-логін і пуші в `main`

## Next Scene
- Action: None — case closed.
- Why: Репозиторій публічний, робочий процес валідації пройдено.
- Expect: Подальшої роботи з публікації немає.
```

Це ілюструє задумане подання поточних доказів і застарілого блокера. Фактичні розвідувальні результати та їхні межі — у [evals/results.md](./evals/results.md).

Скопіюйте репозиторій у директорію скілів інструмента. Портативний контракт — кореневий [`SKILL.md`](./SKILL.md) лише зі стандартними полями фронтматеру `name` і `description`. Ручні Git-установки оновлюються через `git pull --ff-only` із клона. Установки через Skills CLI — через `npx skills update memento`.

| Середовище | Статус доказу |
| --- | --- |

| Поточне середовище агента Codex | Явне виконання скіла протестовано на синтетичних завданнях; результати нижче |
| Автономний Codex CLI | Шлях установки відповідає [поточній документації](https://developers.openai.com/codex/skills); наскрізне виявлення в сесії не тестовано |
| Claude Code | Стандартний формат скілів; рантайм недоступний у цьому середовищі, не тестовано |

Автоматичне викликання залежить від хоста й моделі. Для планової передачі роботи використовуйте явне викликання; автоматичний pre-compaction-хук не входить. Паралельні писарі мають використовувати окремі worktree або явно вибрані шляхи checkpoint'ів.

## Використання

Скіл може активуватися автоматично для тривалої, перерваної роботи чи роботи з крихким контекстом. Можна й явно:

```text
Використай memento, щоб зробити checkpoint цієї міграції перед переключенням агентів.
Віднови це завдання з MEMENTO.md, але спершу перевірь кожен критичний claim.
```

Він веде `MEMENTO.md` у корені активного проєкту. Файл — живий знімок, а не транскрипт чи щоденник лише з дописуванням.

## Межа безпеки

`MEMENTO.md` ніколи не повинен містити креденшели, приватні ключі, cookies, сирі транскрипти, приховане міркування чи великі логи. Виклик скіла не розширює дозволи агента: read-only- і планувальні сесії лишаються read-only.

## Валідація

Розробницькі перевірки використовують PyYAML для парсингу справжнього YAML; встановленому скілу Python-пакети не потрібні:

```sh
python3 -m pip install -r requirements-dev.txt
python3 scripts/check.py
python3 -m unittest discover -s scripts -p 'test_*.py'
```

CI перевіряє метадані, локальні посилання та обробку пошкодженого метаданих. Поведінку агентів він не оцінює. Про поведінкову оцінку — [відтворювані сценарії](./evals/README.md) та [спостережені результати](./evals/results.md).

Початковий розвідувальний підсумок: усі три умови (без пам'яті, звичайний handoff, Memento) пройшли всі три малі сценарії. Свіжий наступник також відновив завершене завдання з агентського checkpoint'у. Ці результати показують робочий приклад, а не перевагу чи економію токенів.

## Дизайн на основі психології

Протокол спирається на три ідеї: source monitoring (звідки це твердження?), cognitive offloading (компактний зовнішній запис) та implementation intentions (при появі сигналу — конкретна дія). [Дослідження, переклад у поведінку агентів і межі](./docs/design.md).

Ці студії стосуються людей. Користь для агентів треба вимірювати окремо; Memento не заявляє клінічно валідованої пам'яті чи гарантованого захисту від prompt injection.

## Допоможіть тестувати

Спробуйте одне перерване завдання, потім опишіть у GitHub issue ваш агент/версію, що наступник зрозумів неправильно, та санітизований checkpoint. Не додавайте креденшели чи вміст приватних репозиторіїв. Корисні результати: коректне завершення, уникнуті повторні розслідування, виміряні витрати часу/токенів. Одні зірки корисність не доводять.

## Джерела дизайну

Дизайн слідує власному опису Нолана: татуювання — для найважливішої інформації, полароїди — для повсякденного контексту, звичка/рутина — як базова система Леонарда, з його [інтерв'ю Fresh Air](https://freshairarchive.org/segments/christopher-nolan). Прямі та зворотні наративні лінії підсумовує [British Film Institute](https://www.bfi.org.uk/sight-and-sound/features/christopher-nolan-time-games).

Проєкт — незалежний програмний скіл, натхненний ідеями фільму. Не афілійований із творцями фільму, студіями чи правовласниками й не схвалений ними.
